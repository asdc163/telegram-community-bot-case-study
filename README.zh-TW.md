# Telegram 社群 Bot

商用社群活動與群管 Bot。一般成員在原群參與，群主透過私訊處理敏感設定。

我負責產品流程與 TypeScript 服務中的角色檢查、持久化投遞，以及移交給其他營運者的流程。使用 Node.js、Fastify、PostgreSQL 和 Docker。

[English](README.md) · [架構](docs/architecture.md) · [交付筆記](docs/delivery-decisions.md)

## 選單還開著，群主可能已經換人

敏感操作套用時會重新檢查目前群主。保留舊設定選單，不會讓失去身分的人繼續管理。普通成員的參與流程仍在群內，不必走過群主介面。

## 發送結果不明，要單獨處理

outbox 持續記錄投遞。限流可以延期，明確失敗可以留下原因；逾時造成結果不明時，直接重送可能讓同一則訊息出現兩次，所以要保留待確認狀態。

群管同時檢查角色與訊息來源。看起來熟悉的名稱或按鈕，不足以證明是可信任的服務訊息。

## 搬機也是交付的一部分

我把停止舊服務、備份、還原與擁有權核對納入交接。平台和應用程式的擁有人需要一致，接手者才能啟動服務。

私有紀錄包含自動回歸、API 角色檢查、部分真人 Telegram 操作及轉移包驗證。接收者操作與剩餘的裝置、語言檢查列於[驗證筆記](docs/verification.md)。

程式與客戶資料保留私有，案例使用通用名稱，不附真實 Bot。開發採 AI 協作，產品行為是規則式邏輯。[公開範圍](DISCLOSURE.md)
